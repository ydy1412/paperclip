# 서버 이미지 가공 잡

1. Auto Sourcing 서버가 설정된 주기마다 가공 전 상품을 찾고 대표·SKU·상세의 사용 이미지를 한 장씩 힉스필드로 변환한다. 원본을 보존하고 결과 PNG와 상품 이미지 참조만 저장한다. 에이전트 실행과 브라우저 창에 의존하지 않는다.
2. 에이전트는 `get-image-processing-jobs`로 현재 프로젝트의 저장된 상태를 읽는다. `queued`는 대기, `processing`은 처리 중, `succeeded`는 저장 완료, `attention/failed`는 확인 필요다. 공급자 생성·폴링·새 요청은 서버에 맡긴다. `process-product-image`의 자동 글자 제거 호출이나 MCP 직접 연결을 하지 않는다.
3. 텍스트·옵션·카테고리는 이미지와 독립적으로 가공한다. 원본 사진의 치수·수량·제한은 원본 근거를 읽어 한국어 설명에 남긴다. 저장 직전 최신 상품을 다시 읽고 서버가 저장한 이미지 참조를 보존한다. revision 충돌이면 한 번 다시 읽어 병합한다.
4. 저장된 assetId는 `get-product-image`로 조회해 실제 원본과 비교한다. 모든 언어 OCR, 제품 형상·색·수량·구성 확인은 이미지 검토 문서를 따른다. OCR 빈 결과와 `succeeded`는 제품 품질 승인과 별개이며 `reviewRequired`를 그대로 전달한다.
5. 화면의 이미지 가공 잡 설정은 운영자가 켜거나 끄고 확인 주기를 바꾼다. 끄면 새 작업을 멈추고 이미 시작한 사진은 마무리한다. 알려진 공급자 실패 또는 글자 잔존의 새 이미지 생성은 운영자의 재시도로 처리한다. 응답 유실·알 수 없는 제출 결과에는 자동 재제출이 없다.
6. 과거 미완료 에이전트 요청은 운영자가 정확한 최초 입력과 원본 해시로 서버 잡에 인계한다. 같은 공급자 요청 ID를 재사용한다. 이슈에는 상품·잡·asset ID, 검토 결과, 남은 문제를 기록하고 자격증명을 넣지 않는다.
