# 최종 이미지 검토와 교정

## 시작 전에

`get-processing-source`의 실제 이미지와 원본 SKU를 읽고 `get-managed-product`의 최초 가격/SKU 스냅샷을 보존한다. 원본의 상품 사진과 사이트 아이콘·로고·광고 배너를 구분한다. 대상의 대표, 각 SKU, 최종 상세에 사용할 이미지 목록을 만든다. 같은 URL을 여러 곳에서 쓰면 하나의 검토 결과로 연결하되 SKU 연결은 모두 기록한다.

원본에 SKU별 사진이 있으면 실제 SKU 사진을 정리하거나 같은 SKU를 보여주는 검증된 컷으로 교체한다. 편집이 실패했다는 이유로 SKU 이미지 필드를 비우고 모든 옵션을 같은 대표 사진으로 돌리지 않는다. 형태가 다른 테이블형/장스탠드나 서로 다른 부품은 사진에서도 구분되어야 한다.

현재 요구는 **최종 사진에 어떤 글자도 없는 것**이다. 실제 사진과 `inspect-product-image`의 치수를 읽고, 숫자·규격·호환 조건은 먼저 한국어 옵션/상세에 보존한다. 이미지의 영문·숫자·단위·로고도 제거한다. 도구 설명의 기존 '치수 글자 보존'은 이 작업의 출력 이미지에 적용하지 않으며, 치수 사실은 원본과 한국어 상세에 보존한다. 서로 다른 설명이 다른 기능·조건을 추가하는지 실제 모순인지 구분한다. 앱 연동과 음성 기기 별도 준비 안내를 근거 없이 상호 배타적인 기능으로 판단하지 않는다.

최종 파일은 서버의 `remainingText`로 전체 언어/숫자 영역을 확인한다. 추가 OCR이 필요하면 `scripts/inspect-text.mjs <이미지 파일>`을 사용한다. 원본을 가져올 때는 조회된 실제 URL만 사용한다. 이 검사기는 기존 macOS Vision을 실행 폴더 안에서 사용하며, 프로그램 설치·서비스 설정 변경·외부 OCR 전송을 하지 않는다. 결과가 비어 있어도 최종 사진을 확대해 직접 확인한다.

## 편집 선택

1. 원본·결과에 글자가 있으면 [내부 Higgsfield 절차](higgsfield.md)로 `provider="higgsfield"`, `removeAllText=true`를 사용한다. 중국어·한국어·영문·숫자·단위·로고 글자가 모두 대상이다. 한 사진의 생성·재조회·실제 PNG 검토를 끝낸 뒤 다음 사진을 처리한다.
2. 제품 밖의 여백이나 설명 패널을 정리하는 크롭은 실제 치수와 제품 경계를 확인한 뒤 로컬 crop 요청으로 처리한다. cloud 글자 제거 요청에 crop/cleanupRegions/removeChinese를 섞지 않는다. 원본 URL을 입력으로 사용하는 API 특성상 이전 cloud 결과를 보존하는지 확인하지 않고 로컬 크롭을 뒤이어 호출하지 않는다.
3. cloud 결과의 모든 언어 OCR `remainingText`와 실제 확대 PNG를 대조한다. 서버가 이미 전체 언어 OCR을 반환하면 그 근거를 저장한다. 별도 OCR이 필요할 때만 `scripts/inspect-text.mjs`를 사용한다. 별도 검사 실패를 글자 없음으로 간주하지 않는다.
4. 제품 손상·잔흔·글자가 남으면 서버 잡 ID와 최초 원본을 운영자에게 전달해 교정을 요청한다. 에이전트가 별도의 생성 요청을 제출하지 않는다. 같은 이미지 생성이 진행 중이거나 제출 여부가 불명확하면 새 요청을 만들지 않는다. 적절한 다른 원본 컷이 있으면 동일 SKU인지 확인한다. 참고 상품 사진이나 다른 SKU 사진으로 바꾸지 않는다.

각 시도는 최초 원본 URL, 현재 `expectedRevision`, 새 `requestId`로 실행한다. 동일 입력의 응답 유실만 같은 ID로 재조회/복구한다. 첫 편집본의 `reviewRequired`를 숨기지 않는다. 서로 다른 시도를 실제로 실행하지 않은 채 '도구 한계'라고 결론 내리지 않는다.

대체 컷을 선택했으면 그 **정확한 URL을 먼저 대표/SKU/상세의 필요한 참조에 저장**하고 최신 revision을 읽은 뒤 처리한다. 처리 API는 현재 상품이 참조하는 원본 또는 그 원본의 현재 파생 참조만 교체한다. `//...` 원본 HTML은 선택한 이미지 참조를 정확한 HTTPS URL로 정리한다. 원본 목록에 있다는 이유만으로 아직 상품에 연결하지 않은 컷을 바로 처리하지 않는다. 크롭은 검사한 원본 치수에서 `x+width ≤ 원본 너비`, `y+height ≤ 원본 높이`인지 확인한다. HTTP 500만 보고 서비스 고장이라고 결론 내리지 말고 URL 연결·최신 revision·실제 치수/요청 영역부터 재조회한다.

## 이미지별 통과 기준

- 원본 대비 제품 전체·색·구성·SKU가 보존되고 숫자/조건의 사실은 한국어 옵션·상세에 옮겨져 있다.
- 실제 출력에 어느 언어의 글자·숫자·단위·로고 글자도 없다. 글자 파편, 빈 광고 배지, 번짐 또는 뭉개진 제품도 없다.
- 크롭 경계가 제품·기능 부품을 침범하지 않는다. 글자 제거를 위해 제품을 잘라 성공을 만들지 않는다.
- 원본이 이미 글자 없이 적절하면 그대로 사용할 수 있지만 전체 OCR과 실제 사진으로 확인해야 한다. 미처리 글자 있는 사진을 '원본 보존'으로 합격시키지 않는다.
- 결과를 상품에 연결한 뒤 `get-managed-product`를 다시 읽어 대표/SKU/HTML의 최종 참조를 확인한다. 이전 URL을 다음 일반 저장에서 다시 덮어쓰지 않는다.

각 이미지에 원본 URL, 최종 URL, 실제 치수, 파생 assetId/해시(있으면), 시행한 교정, `visualPass`, `noText`, `textReviewPerformed` 및 전체 OCR/확대 검토 근거를 기록한다. 숫자가 제거됐으면 한국어 상세의 어느 항목에 옮겼는지 기록한다. 모든 최종 이미지와 모든 SKU 연결이 목록에 있어야 한다. 최종 사진/원본 비교와 검토 파일을 이슈 결과물로 전달한다.

## 운영 재조회 검사 파일

`processing-review.json`의 `projectId`, `accountId`, `products`를 채운다. 각 상품은 `productId`, `sourceProvider`, `sourceProductId`, `sourceHash`, `revision`, 최초 조회의 `originalSkuPrices`(SKU ID → 판매가), `categoryMatchesAllSkus`, `categoryEvidence`(실제 메타데이터와 전체 SKU의 적합성 근거), `images`(최종 `url`, `sourceImageUrl`, 실제 `width`/`height`, `visualPass`, `noText`, `textReviewPerformed`, `notes`; 파생 PNG는 `assetId`도), `skuImages`(SKU ID → 최종 URL), `blockingProcessingIssues`를 가진다. SKU에 별도 이미지가 없으면 실제 최종 대표/상세 사진을 명시한다.

```sh
node "<이 스킬 폴더>/scripts/verify-result.mjs" "$PAPERCLIP_RUN_SCRATCH_DIR/processing-review.json"
```

이 검사는 운영 API에서 상품/원본을 다시 읽어 SKU ID·순서·가격과 이미지 검토 목록을 대조한다. 사람이거나 모델이 실제로 본 PNG를 기록한 `visualPass`의 진실성은 사진 검토로 별도 확인한다. 통과 JSON을 이미지 품질의 독립 증거라고 표현하지 않는다. 하나라도 가공 결함이 남으면 전체 가공 완료로 표시하지 않는다.
