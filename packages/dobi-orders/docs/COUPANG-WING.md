# 쿠팡 윙 연결

0.4.0부터 새 쿠팡 계정은 **윙 아이디·비밀번호 로그인**을 기본으로 사용합니다. 샵마인의 로그인·세션 수집 흐름을 조사한 뒤 별도 코드로 구현했습니다. 이전 공식 API 계정도 계속 사용할 수 있습니다.

## 연결하기

1. **쇼핑몰 · 배송대행 연결 → 쿠팡 → 연결 설정**을 엽니다.
2. 계정 이름, 평소 쓰는 윙 아이디와 비밀번호를 입력하고 저장합니다.
3. **아이디·비밀번호로 로그인**을 누릅니다. 쿠팡에서 추가 인증을 요청하면 휴대폰·이메일을 선택하고 받은 인증번호를 입력합니다.
4. 최초 연결은 로그인된 **판매자코드**를 표시합니다. 윙 계정정보의 코드와 같은지 확인하고 **이 계정 연결**을 누릅니다.
5. **주문 수집**에서 기간을 지정합니다. 한 계정의 전체 응답을 확인한 뒤 주문에 반영합니다. 기존 메모와 보류는 유지합니다.

일반 로그인으로 진행되지 않으면 **윙 로그인창 열기**를 사용합니다. 별도 창에서 아이디·비밀번호와 정상 추가 인증을 직접 입력한 뒤 **로그인 완료 · 연결**을 누릅니다. 창의 쿠키만으로 성공 처리하지 않으며 프로그램이 윙 응답과 판매자코드를 다시 확인합니다. 비밀번호를 저장하지 않아도 이 창을 사용할 수 있습니다.

캡차·추가 인증은 쿠팡이 제공하는 정상 절차로 직접 진행합니다. 로그인창에는 Microsoft Edge WebView2 Runtime과 .NET Framework 4.8이 필요합니다. 이 작업 PC에는 WebView2가 있으며, 프로그램은 전역 설치·설정을 변경하지 않습니다.

## 세션 유지와 다시 연결

로그인 비밀번호와 세션은 Windows 현재 사용자 DPAPI로 암호화합니다. 프로그램을 재시작해도 저장한 세션을 사용하고, 조회 중 갱신된 쿠키도 저장합니다. 세션이 만료되면 저장된 비밀번호로 **한 번** 재로그인합니다. 추가 인증이 필요하면 수집을 중단하고 **윙 로그인**에서 이어서 진행합니다. 닫기·X·Escape는 진행 중 로그인 결과를 무효화합니다. 비밀번호나 인증번호가 잘못되어 요청이 끝나면 새 로그인 화면에서 다시 시작합니다.

이미 판매자코드를 확인한 계정은 **브라우저 세션 다시 연결**도 사용할 수 있습니다. 프로그램에서 연결 요청을 만들고 페어링한 도우미의 **쿠팡 윙 세션 연결**을 선택합니다. 요청은 5분 동안 한 번만 사용하며 기존 판매자코드와 다른 계정은 거부합니다. 최초 연결은 아이디·비밀번호 또는 전용 로그인창에서 진행해주세요.

일반 백업에는 비밀번호·쿠키를 넣지 않습니다. 복원 후에는 다시 로그인해야 합니다. 판매자코드 연결은 복원하여 다른 판매자의 세션이 섞이는 것을 방지합니다. 윙 아이디를 변경하면 기존 세션과 판매자코드 연결을 폐기합니다.

## 구현과 조사 근거

정적 조사 대상은 설치본 26.9.30.906의 `SMWF.MarketInteraction.dll`과 `SMWF.WebBrowser.dll`입니다. SHA-256은 각각 `f5c36c694eb4d5f6df1c0ee0b597a8c3aa198f853bfb9bb3452570b96f41f42b`, `0670c8724e74764d8d863d1df549f340d595191f7b12dcf8cff36d7af677e1a2`입니다. REA의 파일 식별 근거에 연결한 선택 메서드 CIL 보조 분석을 사용했습니다. 전체 디컴파일 성공이나 실행 추적으로 표현하지 않습니다. 원본 프로그램·저장된 계정 DB·브라우저 프로필·인증값은 실행·추출하지 않았습니다.

| 원본에서 확인한 동작 | 별도 구현 |
| --- | --- |
| Wing → xauth 동적 로그인 양식, `username`, `password` POST | HTML 양식 파싱, 고정 HTTPS 호스트, URL 인코딩 |
| `mfaType`, 이어서 `code`, `realActionType=Submit`, `actionType=확인` | 단계별 인증 화면과 5분 유효 요청 |
| bell 응답과 delivery management의 `vendorId` | 명시 성공값 확인, 최초 코드 확인 및 이후 동일 코드 대조 |
| WebView2 로그인창 → 쿠키 전달 | 공식 Microsoft SDK를 사용하는 전용 새 프로필 창, 사용자 확인 뒤 서버 재검증 |
| 신규 주문 cursor·상세, 나머지 배송상태 파일 다운로드 | 전체 페이지/파일, 긴 숫자 ID 원문 보존, 수량·클레임 검증 |
| 취소·반품·교환 조회 | 조회 전용 POST·CSRF, 전체 결과 확인 후 저장 |

원본에서 실제 로그인 **아이디 자체를 서버 값과 대조하는 계약**은 확인하지 못했습니다. 이 프로그램은 입력 아이디를 검증된 서버 아이디로 표시하지 않으며, 서버에서 얻은 판매자코드에 연결합니다. 원본의 반복 로그인·계정 포함 HTML 오류 로그는 복제하지 않았습니다.

주문 조회는 한 번에 최대 93일, 전체 결과 최대 10,000품목으로 제한합니다. 파일 생성·다운로드 요청은 읽기를 위한 것이며 발송·취소 승인·환불 처리는 구현하지 않습니다. 신규 응답에 없는 SKU나 정산 수수료는 추정하지 않습니다. 미완료/뒤 페이지 실패/응답 변경을 빈 정상 결과로 저장하지 않습니다.

## 검증과 남은 범위

합성 HTTP 응답으로 로그인·문자/이메일 단계·쿠키 갱신·판매자코드·주문 전체 수집·실패 롤백을 확인했습니다. Windows DPAPI 저장·재오픈, 브라우저 도우미, 로컬 웹 화면도 검증했습니다. 전용 WebView는 `about:blank` 합성 DOM에서 외부 요청 0건으로 초기화·입력/탐색 정책·쿠키·프로필 해제를 확인했습니다.

**실제 쿠팡 로그인, 현재 사이트의 로그인 양식/MFA/수집 응답, 실주문 수집은 검증하지 않았습니다.** 계정 연결 후 쿠팡의 현재 응답에 맞춘 확인이 필요합니다. 정적 조사와 합성 검증을 실서비스 성공으로 해석하지 않습니다.

소스에서 전용 로그인창을 빌드하려면 Windows x64에서 `npm ci --ignore-scripts` 후 `npm run build:wing`을 실행합니다. 공식 NuGet의 Microsoft.Web.WebView2 **1.0.4258.31**을 크기와 SHA-512로 고정 검증하고 Windows 기본 C# 컴파일러를 사용합니다. `node scripts/build-wing-login.mjs --headless-test`는 실제 Wing 접속 없이 자체 WebView 검증도 수행합니다. SDK·컴파일 바이너리는 소스에 커밋하지 않으며 실행 ZIP에 DLL·로더·라이선스를 함께 제공합니다. [Microsoft 공식 문서](https://learn.microsoft.com/en-us/microsoft-edge/webview2/get-started/winforms), [공식 NuGet 패키지](https://www.nuget.org/packages/Microsoft.Web.WebView2/1.0.4258.31)를 참고해주세요.
