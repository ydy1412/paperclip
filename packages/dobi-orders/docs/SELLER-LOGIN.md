# 판매처 로그인과 주문 수집

0.5.0은 설치본에서 확인한 IMarket 26개 타입을 쿠팡 Wing과 25개 판매처 전용 클라이언트에 연결합니다. 타입 수에는 구형 버전과 API형이 별도로 포함됩니다. 현재 원격 서비스의 운영이나 실계정 성공을 뜻하지 않습니다.

1. **쇼핑몰·배송대행 연결 → 판매처 → 연결 설정**에서 판매처 로그인을 선택합니다. 쿠팡은 Wing 로그인을 사용합니다.
2. 로그인 아이디를 입력합니다. 스마트스토어는 네이버/커머스센터 유형, ESM은 지마켓/옥션, 고도몰·아임웹은 실제 관리자 HTTPS 호스트를 지정합니다. 여러 상점이 있는 네이버·토스·지그재그 계정은 연결할 상점 이름이나 안내된 번호를 입력합니다.
3. 비밀번호를 저장해 일반 로그인하거나 **별도 로그인창 열기**에서 정상 로그인과 추가 인증을 직접 완료합니다. 창에서 로그인 완료·연결을 누른 뒤 앱에서 상점을 확인합니다. CAPTCHA·약관·비밀번호 변경 안내는 자동으로 처리하지 않습니다.
4. 처음 반환된 상점 이름과 번호를 확인하고 **이 상점 연결**을 누릅니다. 이후 로그인과 수집에서도 같은 상점을 대조합니다.
5. **주문 수집**에서 기간을 지정합니다. 모든 지원 목록이 완료되고 계정이 동일할 때만 저장합니다. 실패한 계정의 일부 결과를 저장하지 않습니다. 작업 메모·보류·수동 송장은 유지합니다.

카카오 API형은 원본부터 일반 로그인과 다른 연결입니다. 직접 발급한 프로그램 앱 키와 판매자 앱 키를 입력합니다. 타사 프로그램의 키·파트너 번호·등록 서버를 복제하지 않으며 판매자 등록 요청을 실행하지 않습니다. 일반 카카오 판매처는 별도의 정상 로그인 경로를 사용합니다.

## 계정 확인의 범위

서버가 반환한 판매자·상점·채널 번호가 있으면 이를 연결에 고정합니다. 번호를 반환하지 않는 원본 경로는 정상 인증 상태만 확인할 수 있으므로 사용자 확인이 필요하다고 표시합니다. 설정한 아이디를 서버에서 검증한 계정 번호로 표시하지 않습니다. 이 경로는 새 전용 브라우저 프로필로 연결하고 브라우저 재로그인마다 계정을 다시 확인합니다. 외부 세션 주입은 제공하지 않습니다.

비밀번호·쿠키·토큰은 현재 Windows 사용자 DPAPI 저장소에 보관하고 일반 응답·백업·이력에서 제외합니다. 네이티브 창은 매번 비어 있는 전용 프로필을 생성하고 종료 후 그 프로필만 정리합니다. 기존 브라우저와 샵마인의 저장 계정·프로필은 읽지 않습니다. 로그인 응답 토큰이 필요한 에이블리·올웨이즈는 전용 창의 지정된 로그인 URL 응답에서 필요한 키만 읽습니다. 롯데온은 지정된 원본 키 `AuthToken`만 읽습니다. 브라우저 User-Agent도 암호화 상태에 보존합니다.

세션이 만료되면 저장한 로그인 정보로 한 번 다시 시도합니다. 추가 인증이 필요하면 로그인 창으로 이어갑니다. 취소하면 진행 중 요청을 중단하고 늦게 도착한 결과와 저장 중인 인증을 되돌립니다. 백업 복원은 상점 고정을 보존하되 인증 연결을 초기화하므로 다시 로그인해야 합니다.

## 조회와 발송의 한계

판매처별 조회 기준은 주문일·결제일·발송일·클레임 접수일로 다릅니다. 원래 주문일은 별도로 보존하므로 조회 기간 이전의 주문일이 나타날 수 있습니다. 반환된 안내에 기준과 원본 미지원 상태를 표시합니다. 원본의 빈 성공 함수를 전체 상태 지원으로 표시하지 않습니다.

마스킹·배송지 누락·부분 수량·클레임은 발송 가능 수량을 보수적으로 제한합니다. 품목 연결이 없는 주문 단위 클레임은 이전에 저장한 같은 계정·주문번호의 다른 품목과 기존 배송 초안의 전송도 막습니다. 긴 식별자와 앞자리 0을 보존하며, 이미 정밀도가 손실된 엑셀 숫자는 복원했다고 추정하지 않습니다.

암호화 ZIP·Office 파일은 수집 요청마다 임시 암호를 사용하고 메모리에서 처리합니다. 일부 판매처는 서버에 Excel 생성·다운로드 이력이 남습니다. 파일 크기·압축 해제·행 수·페이지 상한과 전체 건수 일치를 확인하며 모호하거나 불완전하면 중단합니다.
