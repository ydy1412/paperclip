## 성공 판정과 주문 안전성

인터파크와 위메프 두 방식은 원본에서 인증된 화면의 로그아웃 표시만 확인하며, 원격 사용자 ID를 대조하는 계약을 확인하지 못했습니다. 티몬도 로그인된 주문 그리드는 확인하지만 원격 계정 식별 계약은 확인하지 못했습니다. 이 네 방식은 `identitySource=credential-login`과 `serverAuthenticated=false`로 표시하며, 입력한 ID 자체를 원격 증명으로 주장하지 않습니다. 최초 연결과 다른 로그인 창으로 새로 연결할 때 사용자의 계정 확인을 받습니다.

SSG·티몬의 배송완료 전용 경로를 임의로 만들지 않습니다. SSG의 `0x060013e0`, 티몬의 `0x06000fd8` 배송완료 분기는 실제 조회 없이 빈 성공을 반환하는 원본 경로입니다. 구현은 해당 한계를 안내하고, 다른 목록에서 실제 반환한 상태는 보존합니다. 원본에 있던 약관 자동 동의, 비밀번호 변경 생략, 인증 생략은 실행하지 않습니다. 인터파크의 비밀번호를 GET URL에 싣는 사전 유형 확인도 복제하지 않으며, 기업 계정 유형은 정상 로그인 창에서 선택합니다.

오늘의집은 작업마다 난수 Excel 암호를 요청하고, Office Agile·Standard 암호화를 해제한 뒤 원시 OOXML 셀 값을 읽습니다. 해제 전 파일 크기·평문 길이·암호 연산 횟수 상한을 확인합니다. 원본 요청의 페이지 크기 500과 다운로드 행 수가 정확히 같으면 전체 결과인지 확인할 수 없어 기간을 나누도록 중단합니다. 티몬 클레임도 원본에 별도 페이지 계약이 없어 페이지 경계 크기 응답은 전체 성공으로 표시하지 않습니다.

구형 위메프의 화면 경로는 서버가 반환한 딜·옵션을 확인한 뒤 원본 상품 초안의 판매가와 연결합니다. 옵션 가격이 불명확하면 0원으로 대체하지 않습니다. 화면에 우편번호가 없으므로 이 방식의 화면 주문은 발송 대상을 자동 활성화하지 않습니다. 원본의 취소 전용 경로는 취소 요청 화면이며, 다른 처리 상태까지 조회한다고 확대 해석하지 않습니다.

필수 필드·식별자·페이지 종료·상점·마지막 요청의 실패를 전체 오류로 처리합니다. 주문번호와 품목번호는 문자열을 유지합니다. 마스킹된 개인정보, 클레임, 수량 불일치와 불완전한 수령 정보가 있으면 발송을 차단합니다. 티몬·구형 위메프에서 클레임 품목을 원래 품목 ID와 확실히 연결할 수 없으면 `orderLevelClaim=true`를 기록하여 같은 주문 전체를 검토 대상으로 둡니다. 고객 이름·원시 응답·인증 토큰·일회용 코드·비밀번호를 로그나 fixture에 기록하지 않습니다.

집중 합성 테스트에는 정상 인증 요청과 해시 변환, 보안 인증 전환, 원격 식별·수동 확인 구분, 전체 지원 상태, 긴 식별자와 우편번호, 후속 오류의 원자적 실패, 잘못된 상세·딜·옵션 연결, 마스킹·클레임 발송 차단, Excel 암호·크기·연산 한도가 포함됩니다.
