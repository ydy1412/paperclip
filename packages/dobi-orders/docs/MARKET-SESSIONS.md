## 연결 방법

판매처 연결에서 계정 로그인 방식을 선택하고 아이디를 입력합니다. 정상 HTTP 로그인 계약이 확인된 곳은 비밀번호로 로그인하며, 추가 인증 또는 브라우저 인증이 필요한 곳은 프로그램의 정상 로그인창을 사용합니다. 처음 연결하는 판매자·상점은 화면에 표시되는 번호와 계정을 확인한 뒤 저장합니다.

브라우저 인증은 프로그램이 만든 독립 프로필에서 진행합니다. 다른 브라우저 프로필이나 샵마인 계정 DB의 쿠키·토큰을 읽어 복사하지 않습니다. 비밀번호·인증 쿠키·API 키·토큰은 일반 연결 응답이나 백업에 포함하지 않습니다.

## 추가 입력이 필요한 연결

- 고도몰·아임웹은 실제 관리자 쇼핑몰의 HTTPS 호스트를 입력합니다. 공통 회사 홈페이지 주소로 대신하지 않습니다.
- 지그재그 다점포는 정확한 상점 이름 또는 서버 상점 번호를 입력합니다. 처음 나온 상점을 임의로 고르지 않습니다.
- 토스쇼핑 다점포는 판매자명을, 네이버페이 다중 가맹점은 가맹점 ID를 연결 설정의 상점 정보에 입력합니다.
- 카카오톡스토어는 로그인창에서 비즈그룹·상점을 선택하고 관리자 추가 인증까지 끝내야 합니다.
- 카카오 API는 본인이 사용할 수 있는 `appKey`, `sellerAppKey`, 필요 시 `channelIds`를 입력합니다. 샵마인의 앱 키·파트너 ID·채널 값을 복제하지 않습니다. `partnerId`는 현재 읽기 요청에 사용하지 않으며, 판매자 등록 API를 자동 호출하지 않습니다. 이 API의 현행 사용 협의·권한 조건은 별도 확인이 필요합니다.
- 오늘의집 암호 Excel 비밀번호는 해당 수집 요청마다 난수로 생성해 서버에 지정합니다. 다른 문서의 비밀번호를 추측하거나 암호를 우회하지 않습니다.

## 신원 확인 수준

서버 판매자·상점 번호를 확인한 연결은 `identitySource: server`입니다. JWT 내용을 읽은 것만으로 서버 신원을 확인했다고 처리하지 않습니다. 에이블리는 JWT `seller_id`가 선택한 서버 계정 응답의 `sno`·이메일까지 대조합니다.

원본이 로그인 여부만 제공하는 판매처는 서버 판매자 번호를 만들어내지 않습니다. 비밀번호를 직접 전송한 세션의 `credential-login`, 또는 독립 로그인창에서 사용자가 확인하는 `user-confirmation`을 명시합니다. `login:<입력 ID>` 같은 값은 사용자가 고정한 연결 식별자이며 서버가 반환한 계정 번호가 아닙니다.

새 연결·브라우저 재인증의 계정 확인은 상위 연결 서비스가 담당합니다. 저장된 계정 식별자와 다른 서버 번호가 나오면 수집을 중단합니다. 수집 전후의 인증·신원 검증을 통과해야 전체 결과를 저장합니다.

## 전체 수집과 출고 보호

클라이언트는 필요한 모든 요청이 끝난 경우에만 `{complete: true, orders, notes}`를 반환합니다. 인증 화면, 응답 구조 변경, 필수 정보 누락, 반복 페이지·커서, 전체 건수 불일치, 조회 한도 도달, 중간 상태 조회 실패는 전체 실패입니다. 조회 실패를 빈 정상 결과로 바꾸지 않습니다.

주문번호·품목번호·송장·전화·우편번호는 문자열로 보존합니다. JSON의 큰 정수와 OOXML 원시 값은 숫자로 반올림하지 않습니다. 구형 BIFF Excel에서 이미 정밀도를 잃은 긴 숫자 셀은 추정 복구하지 않고 거절합니다. Excel 수식·매크로·외부 참조·다중 시트 또는 과도한 압축·행 수는 실행하지 않고 중단합니다.

클레임·부분 수량·마스킹되거나 빠진 배송지는 자동 출고에서 제외합니다. 확인되지 않은 신규 상태도 발송 가능으로 추정하지 않습니다. 품목을 특정할 수 없는 원본 클레임은 주문 전체에 대한 보호 정보로 반환합니다. 처리 완료·철회 기록의 해석이 불명확하면 보수적으로 확인 대상으로 남깁니다.

- SSG·티몬은 배송완료 전용 메서드의 전체 조회가 원본에서 확인되지 않았습니다. 티몬은 별도 D4 배송 상태를 수집하지만 이를 별도 배송완료 조회와 동일시하지 않습니다.
