# 스마트스토어 판매자센터 로그인

스마트스토어 계정은 네이버 아이디 또는 커머스센터 아이디로 연결합니다. 기존 공식 커머스 API 연결도 유지됩니다. 판매자센터 연결에는 API 앱 키가 필요하지 않습니다.

1. 스마트스토어 연결을 만들고 계정 유형, 로그인 ID를 입력합니다. 여러 스토어가 있는 계정은 연결할 스토어명을 정확히 입력합니다.
2. 네이버 아이디는 로그인창에서 정상 로그인과 추가 인증을 완료합니다. 센터 아이디는 저장한 비밀번호로 일반 로그인 요청을 보내며 해외 접속 확인·CAPTCHA·추가 인증이 필요하면 로그인창에서 이어갑니다. 인증 제한을 우회하거나 CAPTCHA를 자동 해결하지 않습니다.
3. 로그인 후 서버 계정 헤더, 채널과 상점 고유번호를 확인합니다. 고유번호는 `merchantNo:channelNo`입니다. 로그인 ID를 서버 계정 검증 결과로 대신 반환하지 않습니다. 서버 계정 헤더가 없는 응답에서는 상점 번호 확인 범위를 넘어서 계정 ID까지 검증했다고 안내하지 않습니다.
4. 이후 연결 확인과 수집에서도 저장한 상점 고유번호를 대조합니다. 다른 상점이 나오면 전체 작업을 중단합니다.

센터 로그인은 `accounts.commerce.naver.com/graphql`의 `foreignCaptcha`와 `idLogin`, 로그인 후 판매자센터 진입을 사용합니다. 원본의 요청 본문과 Content-Type 차이를 보존했습니다. 다중 스토어는 `/api/login/channels` 목록에서 선택하고 `/api/login/change-channel` 후 현재 채널을 다시 확인합니다. 쿠키 존재, 창 종료 또는 설정한 계정 이름만으로 성공 처리하지 않습니다.

## 주문 수집

판매자센터 `/o/v3/graphql`의 원본 조회 계약을 사용합니다. 신규 주문, 발주 확인, 발주 확인 해제, 배송중, 배송완료, 구매확정과 취소·반품·교환 각 처리 상태를 합쳐 21개 조회 프로필을 전부 확인합니다. 500품목씩 모든 페이지를 읽고 총계·페이지·중복·변경을 검증한 후 결과를 반환합니다. 어느 한 조회라도 실패하면 부분 결과를 정상 결과로 반환하지 않습니다. 한 번에 10,000품목까지 수집합니다.

일반 주문의 기간은 원본의 `PAY_COMPLETED` 기준인 **결제일**입니다. 화면 주문일에는 원본 `orderDateTime`을 보존하고 결제일은 `sourceIds.paidAt`에 남깁니다. 결제 전날 생성한 주문이 누락되지 않습니다. 클레임은 조회 종료 후 발생한 변경도 놓치지 않도록 접수일을 오늘까지 조회한 뒤 해당 결제일 범위의 주문에 반영합니다. 최근 2년 이내의 기간을 지원합니다.

주문번호와 상품주문번호는 18자리 숫자로 도착해도 문자열로 보존합니다. 품목 키는 상품주문번호입니다. 원본 주문금액 계산 `(상품단가 + 옵션금액) × 수량`과 할인 후 `productPayAmt`를 구분하여 보존합니다. 수수료·정산액은 이 계산으로 추정하지 않습니다.

활성 또는 완료 클레임은 발송 가능 수량을 0으로 지정합니다. 부분 클레임, 알 수 없는 상태, 배송지 누락도 수량을 추정하지 않습니다. 철회된 클레임은 정상 주문을 덮어쓰지 않으며 철회 내역만 확인된 품목의 발송도 막습니다. 구매확정·클레임 일부 응답에는 배송지나 통관번호가 없을 수 있습니다. 이 구현은 상세 팝업의 HTML에서 누락된 개인정보나 정산 수수료를 추가 추출하지 않습니다.
